Yes bro. Now we should treat **PS #90 as a real product**, not just an AI demo.

The first important decision is:

> **Build an Android-first mobile app for artisans + a web-based admin/marketplace dashboard + a backend API + AI services.**

Don't make only a website. The problem specifically targets artisans with low digital literacy, and a mobile app gives us camera, microphone, notifications, and a much simpler experience.

### Step 5 — E-commerce formatting

Example:

# 8. How do we implement Image AI?

For the hackathon, **do NOT train our own image model from scratch.**

That would waste time.

We can build an AI pipeline using existing models/APIs.

Conceptually:

```text
Upload Image
     ↓
Image Validation
     ↓
Background Segmentation
     ↓
Background Removal
     ↓
Image Enhancement
     ↓
Resize/Crop
     ↓
Final Product Image
```

Possible technologies:

### Option A — Cloud AI

Use an image-processing API.

Advantages:

* easier
* faster
* better results

### Option B — Open-source models

Run models on our backend.

For example:

```text
Python
PyTorch
OpenCV
Segmentation model
Image enhancement model
```

This gives us more control.

For SIH, I'd use **existing AI models + our own orchestration** rather than pretending we trained everything ourselves.

# 11. LLM Product Cataloger

Suppose speech recognition produces:

```text
This is a handmade cotton bag.
It is made in Odisha.
It takes two days to make.
The bag has traditional patterns.
```

We send this to an LLM with a structured prompt.

The AI returns something like:

```json
{
  "product_name": "Handmade Traditional Cotton Bag",
  "category": "Handicrafts",
  "material": "Cotton",
  "origin": "Odisha",
  "production_method": "Handmade",
  "description": "...",
  "keywords": [
    "handmade",
    "cotton bag",
    "Odisha handicraft",
    "traditional"
  ]
}
```

This is much better than simply asking an LLM:

> "Write a description."

Because our backend needs **structured data**.

# 16. Do we actually need Machine Learning?

For MVP:

### Not necessarily.

We can initially build:

```text
Rule-based pricing
+
Market statistics
+
Regression model
```

For example:

```text
price =

material_cost × 1.3
+
labour_cost
+
market_adjustment
+
quality_adjustment
```

Then later replace this with an ML model.

Possible model:

```text
Input:

material
category
production_time
material_cost
region
quality_score
market_price
demand
season
```

Output:

```text
recommended_price
```

Model:

```text
Random Forest
XGBoost
Gradient Boosting
```

For a hackathon, **XGBoost/Random Forest + a good dataset** is more practical than deep learning.

# 32. Very important: AI safety

Our AI should **never silently invent product information**.

Suppose artisan says:

> "This is a cotton bag."

The AI shouldn't suddenly write:

> "100% organic premium cotton certified product."

unless the artisan actually provided that information.

So we should separate:

### Verified information

```text
Material: Cotton
```

from:

### AI-generated marketing content

```text
Beautiful traditional handmade bag...
```

And mark uncertain information.
